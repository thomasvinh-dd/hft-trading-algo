# 407 Proxy error → no DNSE submit (2026-10-13)

## What happened

On 2026-10-13 the autofin bot's mid-day poll at 09:00 ICT
fetched signals from autofin.vn but the bot did NOT submit
any orders to DNSE.

The user audit on 2026-10-13 confirmed the autofin API was
returning 4 signals (ABB, TLG, BAF, ABW) — so the autofin
service was NOT the bottleneck.

## Root cause: stale proxy in .env.dnse-secrets

The `.env.dnse-secrets` file had the OLD Vietnamese proxy URL
that was supposed to be cleared in commit `c8a8d56` (proxy
cleanup on 2026-10-12). However the file was overwritten
back to the URL by some process — possibly the bot restart
that re-sourced the env. Whatever the cause, the env file
had:
```
DNSE_PROXY_HTTP_URL=http://VN18996:jZhQ1b3Y@180.214.237.169:12345
```

The proxy was defunct (the $2.75/month subscription was
cancelled in 2026-09-04 when the VPS IP got whitelisted on
DNSE). So all DNSE requests via the proxy returned:
```
HTTP 407 Proxy Authentication Required
```

The DNSE side-effect was:
1. `run-get-otp` failed with the 407 — token file remained
   stale (from 2026-08-31)
2. `place_stock_order` would have failed the same way
3. The autofin bot was unable to submit ANY orders to DNSE

## Fix

Set `DNSE_PROXY_HTTP_URL=` (empty) in the env file. The
DnseClient constructor now sees the empty string and skips
the proxy install:
```python
if os.environ.get("DNSE_PROXY_HTTP_URL"):
    if configure_http_proxy_from_env():
        use_proxy_opener()
```

## Verification

After the fix:
- `run-get-otp` succeeded and wrote a fresh token dated
  2026-10-13
- `force-run-trading --live-submit` planned ABB BUY 100 @
  17,700 VND + ABB SL SELL 100 @ 15,930 VND
- ABB BUY FILLED — order 133161, status Filled, fillQuantity 100
- The SL was rejected ("TRADE_QUANTITY_NOT_ENOUGH") because
  we had no position yet — the bot's order monitor / next
  poll will re-attempt the SL now that we hold 100 ABB

## Why this slipped through

The original "fix" on 2026-10-12 used `sed -i` to clear the
URL. That worked at the time, but the env file was reverted
to the URL at some point between then and the next bot
restart. The cause is unknown (no automation writes to that
file, and the bot itself just reads env vars). The cron
script (`scripts/launch_autofin.sh`) sets the URL to empty
in its `nohup env ...` block, so the LAUNCHED process should
have the right value — but the on-disk env file is the
source of truth that `run-get-otp` reads.

## Lessons

1. **Always check the env file before any "the API is broken"
   diagnosis.** A 407 proxy error is upstream of the autofin
   service.
2. **The launch script's `DNSE_PROXY_HTTP_URL=""` override
   only affects the bot's in-process env, not the env file.**
   For one-shot scripts like `run-get-otp`, the file matters.
3. **Add a startup check** (open work item) that fails fast
   if `DNSE_PROXY_HTTP_URL` is set in the env file, since
   that file is read by the standalone scripts.
