## Live DNSE Execution Safety

### Initial Orderbook Pricing

Added initial orderbook pricing before submit:

```text
BUY  -> DNSE best ask
SELL -> DNSE best bid
```

Added max drift protection:

```text
BUY cannot chase above signal price + max drift
SELL cannot dump below signal price - max drift
```

Recommended live flags:

```bash
--initial-orderbook-pricing \
--max-price-drift-percent 2 \
--monitor \
--max-checks 3 \
--check-interval-seconds 5 \
--cancel-if-unfilled
```

### Sellable Quantity Cap

Added live DNSE sellable quantity cap:

```text
before real submit, fetch DNSE positions
SELL orders are capped to sellableQuantity / availableQuantity
quantity is rounded down to board lot
SELL is skipped when sellable quantity is zero
```

This applies to:

```text
normal strategy sell orders
corporate-action forced exits
```

Before:

```text

```

Now:

```text
remainingQuantity = originalQuantity - matchedQuantity
replace only remaining quantity
if remainingQuantity <= 0, skip replace
```

Supported DNSE field names:

```text

filledQuantity
matchQuantity
filledQty
matchedQty
```

Implemented live risk controls:

```text
TRADING_ENABLED
MAX_ORDER_NOTIONAL
MAX_DAILY_NOTIONAL
MAX_ORDER_COUNT
```

Real submit is blocked unless:

## Corporate-Action Trading-Day Windows

Added trading-session based corporate-action window helper:

```text
non_cash_events_in_trading_window
```

Fix made after discovering a bug:

```text
Past corporate-action events were incorrectly remapped to the current trading date.
This made old events appear active again and destroyed returns.
```

Buggy behavior:

```text
event exDate: 2026-09-01
trade date: 2026-09-04
old code mapped event to 2026-09-04 and triggered it
```

Fixed behavior:

```text
find ex-date index from full trading calendar
sessions_until = ex_index - trade_index
past events produce negative sessions_until and are ignored
```

Backtest now uses actual price trading dates for corporate-action windows.

Live submit now builds a trading calendar from:

```text
weekdays minus market_holidays_vn.json
```

and passes it to:

```text
dnse-preview-orders
dnse-submit-orders
```

### Reserved Slot Fix

Discovered the strict CA reserve logic still changed portfolio path because it reserved cash but not portfolio slot/sector slot.

Example issue:

```text
No CA PDR position in 2020 had 8100 shares.
CA version initially held only 5100 shares.
The CA sell/rebuy prices were reasonable, but position size was much smaller.
```

Implemented reserve slot and sector slot:

```text
reserve cash
reserve one position slot
reserve original sector capacity
normal strategy cannot use those while reserve is active
rebuy adjustment can use reserved cash
rebuy uses all reserved cash, not fixed target quantity
```

Result after reserve slot fix with relative-strength config:

```text
Return: 192.77%
Max DD: -25.91%
TradeCount: 1399
```

Comparison:

```text
Strict CA before reserve-slot fix:
  Return: 183.45%
  Max DD: -28.71%

Strict CA after reserve-slot fix:
  Return: 192.77%
  Max DD: -25.91%
```

Conclusion:

```text
reserve slot/sector was necessary for CA sell/rebuy to behave like a temporary adjustment.
```
